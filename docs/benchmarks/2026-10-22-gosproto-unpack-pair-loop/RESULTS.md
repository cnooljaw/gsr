# 普通mask每轮恢复两个有效字节

本轮完成候选实现、正确性及性能筛选，**暂不应用到生产库**。整数数组PDecode有双遍小幅正向信号，4～6有效字节的合成形态也有局部收益，全部保留；但主目标Unpack尚未确认收益，大型组合第二遍及单word存在反向，self控制有明显波动。判断与固定5%或任何收益门槛无关，也不宣称候选必然没有收益。

## 唯一改动

基线正常库 `9e47281`。普通mask仍按TrailingZeros8顺序获取一个有效位，读取同一src[used]并写入同一dst[index]，清除最低置位后检查结束；如果还有位，再执行一份相同逻辑，然后才回到循环头。每轮最多两项，奇数项先检查再退出，不多读写。零段、FF、完整首遍预检、预算、make、错误先后、精确len/cap及独占输出均未改。

[candidate.patch](candidate.patch)为零上下文补丁（手工应用需 `git apply --unidiff-zero`），只有增加七行；[完整候选pack.go](candidate-pack.go.txt)。未增加表、池、unsafe、公开API、消息/密度特判或额外分配。

ARM64 objdump机器指令行（含填充）388→408，静态panic调用点14→16，栈仍112B，函数入口地址两版本相同。展开确实增加代码体积/失败路径，不能将少回跳直接等同于少指令或更快；静态调用点不是动态执行次数。[汇编摘要](assembly-summary.json)。

## 方法和覆盖

两个完整Git归档均从9e47281构建，只给B应用上面的pack.go改动。正常包名/公开入口，没有实验选择器。self用同一A二进制按A/B标签运行；pass1/pass2用独立正常A/B二进制。每模式三轮ABBA/BAAB，20项/进程，Go benchmark每项目标100ms、自行校准调用数，GOMAXPROCS1/GOGC100/GOMEMLIMIToff。36进程720行测量，51条构建/验证/计时命令全部通过；两遍源码、fixture与二进制SHA采样前后相同。

20项包含三种真实消息Unpack/PDecode（6），旋转有效位置的1～7有效字节×256word（7），单word的1/3/7有效字节（3），32/4096B零块及FF密集ASCII（4）。真实消息复用既有wire/语义检查；合成输入在计时前验证字节与精确cap。全部20项A/B的B/op和allocs/op一致。

全表、逐轮、self和近似累计见[ALL-CASES.md](ALL-CASES.md)与[analysis.json](analysis.json)。累计按已打印ns/op×调用数估算，受Go文本舍入影响。原始样本全部保留，不扣减self，不删除长尾，也不跨模式挑最佳值。该100ms跨进程筛选有明显离散，不能代替延长块、同进程固定调用数或更多布局控制的正式归因实验。

## 主要结果

负值为候选耗时降低。下表每遍为三轮配对比值中位 / 近似累计比值。

| 入口 | 第一遍 | 第二遍 |
| --- | ---: | ---: |
| 整数数组 Unpack | +1.90% / +3.26% | −0.01% / −0.20% |
| 整数数组 PDecode | −0.81% / −1.21% | −2.64% / −3.13% |
| 大型游戏 Unpack | −0.53% / +11.69% | −0.02% / +0.20% |
| 大型游戏 PDecode | −0.53% / −1.92% | +15.92% / +12.54% |
| AddressBook Unpack | −0.08% / −1.20% | −0.71% / +6.23% |
| AddressBook PDecode | −0.39% / +48.04% | +0.58% / +2.02% |
| 单word 3有效字节 | +13.67% / +10.77% | +3.18% / +5.07% |
| 单word 7有效字节 | +4.69% / −2.96% | +5.78% / +1.07% |

局部正向也不能遗漏：4有效字节合成Unpack中位−1.98%/−3.05%，5有效字节−2.89%/−0.49%，6有效字节−1.94%/−5.65%。其中5有效字节第二遍累计+3.15%；整数数组PDecode第二遍三轮为−19.61%/−2.64%/+29.50%，离散明显，不能只看中位数。

self中AddressBook Unpack中位−10.61%、FF4096为−12.40%、3有效字节×256为+18.15%，其余控制和逐轮亦完整公布。不扣控制“修正”结果，也不据未改的FF/零段波动给出硬件原因解释。未确认主目标收益，且有短包风险，继续叠加四项展开缺乏依据。

## 正确性验证

A/B各运行既有全部mask/精确边界/预算/坏尾部/独占回归以及相关官方兼容与格式错误测试，race+严格checkptr通过；harness fixture和vet、编译、全部benchmark计时前语义检查通过。[日志](commands.json)。

优先复用 `TestUnpackWordViewBounds`：全部256mask×1/2/7/8/9/255/256/257重复word×不同零前缀/输入容量，检查恰好预算、不足预算、截断、结果不别名、精确cap和失败无部分输出。它已覆盖候选涉及的奇偶有效位及边界，因此不新增同义永久测试。候选未应用，没有进入发布验收，不额外重复全库fuzz/GoTS集成，也不声称已完成这些未跑项。
