# Unpack 首遍普通 mask 预检实验

2026-10-20，基线 gosproto `5360fe0`。本轮完成两版预检候选，**暂不并入生产**：小型消息Unpack有约2%～3%的重复正向，但大型/整数数组和组合路径没有一致收益，局部代价及控制离散仍在。不是因为收益低于某个比例而舍弃；小型消息收益完整保留，后续可继续作为线索。

上一轮诊断已提交GSR `6c40523`，未推送。本轮报告、实验源码和文档留审查，尚未提交。独立库仍5360fe0及原六项用户删除，正式依赖v0.4.0不变，没有新生产实现或PB/TS排名。

## 两版候选

首版：在预检循环前单独识别普通mask，按常量8计算产出，执行原顺序的输入长度与预算检查，然后continue；零段/FF继续原路径。仅复制必要检查，第二遍写出逐字节与原源码相同。它增加了重复的分支/检查代码，ARM64机器字行388→420，栈112B及静态检查点不变。

首版完整21入口、84进程、8064块、115条流程命令保留在 [initial/](initial/ALL-CASES.md)。大型Unpack两轮中位+0.36%/+1.30%，整数数组+1.34%/+2.04%；小型Unpack−3.13%/−1.83%、组合−1.72%/−1.09%，但次轮累计分别+1.80%/+2.11%。3非零字节word−3.05%/−5.35%等正向也保留，未只记录失败项。

精简版：取消独立普通mask循环与重复检查，只将分类改为普通mask优先，并共用原来的输入边界、预算、尺寸和推进检查：

```go
// header为byte；加一回绕后，只有普通mask落在2～255。
if header+1 > 1 {
    consumed += bits.OnesCount8(header)
} else if header == 0 {
    // 原零段处理
} else {
    // 原FF处理
}
// 原输入边界、预算和游标推进
```

header=0/255时加一分别为1/0，1～254则为2～255；这依赖Go的uint8回绕语义，不可直接换成int后沿用。全部256种mask回归覆盖分类边界。精简版机器字行仍388、栈112B、panicIndex4和panicSlice*10静态点均与基线相同；不能据此预言动态提速。

两版都保留完整首遍、零段有界扫描、FF边界、精确分配、cap、输出独占及错误优先级；没有新API、unsafe、池或缓冲复用。第二遍写出源码与基线完全相同，没有混入上一轮连续源窗口候选。编译后的寄存器/布局仍可能因函数其他部分变化而不同，不能声称相同源码就保证相同机器码。

## 增量回归与验证

先查找并复用现有UnpackWordViewBounds、Pack/Unpack预算等用例。新增的窄回归补足原测试未显式覆盖的冲突错误顺序：254种普通mask、每入口合计2540次调用，截断与本word预算不足同时存在时仍返回ErrUnpack；完整word预算不足返回ErrLimit；已有单零word或FF前缀先超预算时仍优先ErrLimit，前缀恰好接纳后才报告坏尾部。失败始终不返回部分输出。这里是每入口合计2540次调用，不是每mask2540次。

两版三入口（baseline/clone/candidate）均先通过该回归及现有全部mask/零段/长度/容量/预算/截断/cap/独占回归的race+严格checkptr，再完成代表夹具、vet、编译及全部输入语义预检。新增回归先在baseline成立；未采纳候选，测试源码仅随报告保留，未向生产增加重复测试。

每版各84进程、504轮、2016四元组、8064块、115条准备/预检/测量日志命令均成功，两版合计168进程、16128块、230条日志命令。单一SP模块、同进程共享schema/分配器，clone函数体与基线相同。每臂预热50ms，基线256次校准约20ms，两臂相同固定调用数；6轮×4个ABBA/BAAB四元组，GOMAXPROCS1/GOGC100/GOMEMLIMIT=off。组合路径是选定UnpackWithLimit(default预算)+公开Decode，未直接调用DecodePacked来注入候选，不以绝对值作公开API新排名。

源码、harness、生成输入、夹具、唯一SP模块和二进制指纹前后核对，全部块比例独立复算至1e-12。初版数据按原样移到initial，保留原始和迁移后清单；没有删样本或回填结果。本轮无新生产代码，未运行完整库/oracle/fuzz/GoTS验收，accept.py为尚未执行的验收脚本。

## 下一方向

不再围绕普通mask分类的条件表示继续叠加微调。下一候选考虑把预算证明移到入口：若`len(src) <= maxBytes/8`，由于任何合法packed段的产出都不超过其输入字节数的8倍，整个输入的输出预算已由一次上界检查保证；窄预算或无法证明时保留原逐段预算路径。条件用除法避免8×len溢出，仍须验证每段完整边界，错误优先级、精确输出和独占分配都保持。

这是待验证的工程方案，不是直接跳过资源限制：需要先逐类证明普通、零段、FF的上界，覆盖整数溢出和相互冲突的错误，再测默认预算与严格回退路径的成本。若证明或收益不成立则不采用。该方案本轮尚未实现，未声明任何新收益。Body Decode继续开放。
