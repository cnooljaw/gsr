# TS Sproto Pack 字节分布与解包视图验收

第四轮已本地提交为 `d9655b8`，提交后工作树干净，未推送。本轮按 Pack 字节分布、public/manual 路径、零块 Unpack 的优先级继续；没有修改 Go、公开 API、官方 wire、预算或缓冲保留上限。新修改留在工作树审查。

## 实现与取舍

- 逐 word helper 只生成 mask 和非零字节；FF 段内六/七字节 word 的合并判断集中到 Pack 段状态所在循环，删除 helper 内重复状态检查和 FF 全非零探测。已有长 FF 原生扫描继续保留。
- 普通混合 word 提前更新输出游标，跳过 FF 收尾和长零段处理；短 FF word 先判定，避免普通路径增加无效检查。没有按消息名、整数类型或特定 mask 分布特判，没有新表、缓存或依赖，原容量保护保留。
- 曾尝试在公开/私有解包缓冲长度刚好匹配时省略 subarray 视图，但两类候选未通过完整形态验收，均已撤回。公开 unpack、私有解包与 lunpack 的最终方法体都与基线逐字节相同。
- 本轮没有减少解包路径的字节分配、视图或扫描次数；不把视图对象和数据复制混为一谈。没有为改善 manual 的数字而改变输出所有权或调用入口。

## Pack 的真实输入与热点

分布使用编码后的原始字节计数，包括最后不足八字节的补零 word；wordCalls 为实际完整 word helper 次数，不包含尾部或批量跳过。分布包装只用于计数，CPU profile 使用新实例，不在计时中插入探针。完整 mask 直方图见 [analysis-before.json](analysis-before.json)。

| 小型游戏状态 | 328 | 216 | 41 | 41 | 0, 1, 4, 6, 12, 14, 2, 0, 2 |

896 项整数数组共 450 word，没有全非零 FF word；大型游戏消息 417 word 中只有两个全非零 word，主要是 4–6 个非零字节的混合 word。整数数组最常见的七种 mask 为 11/1f/21/7e/c7/e2/fc，各 64 次。这里改善的是通用混合字节路径，不能统称为数值专用 Pack。

官方 Sproto 的 pack_seg 同样逐字节生成 mask，FF 通过 memcpy 批量输出；本轮不改这种布局。V8 inlining 探针确认原 pack_seg 已可内联，不能将 profile 中 helper 的归因直接解读为函数调用成本。Protobuf-ES 的固定宽度写出和 bytes 子视图可供参考，但它没有 Sproto 的零字节 packing，不能用 PB 的纯编码速度要求这一步没有成本。

独立 Pack 与 pencode 分别采 CPU profile，摘要见 [修改前](analysis-before.json) / [修改后](analysis-after.json)。函数可能按内联位置归因到 pack 或 pack_seg；self 和 cumulative 不能相加。独立步骤中位数相除只提示开销大小，不能当作业务 pencode 的 CPU 占比，也不能直接相加预测整条路径。

## Buffer 观测与公开路径的取舍

热身后单次同步调用，计数显式 Buffer.allocUnsafe 和 Buffer.prototype.subarray；它不是完整 JS 对象分配数、堆采样 B/op 或峰值内存。公开输出的字节缓冲继续独占，私有缓冲仍最多保留 16 KiB。

| 路径 | alloc 调用 前→后 | 请求字节 前→后 | subarray 调用 前→后 |
| --- | ---: | ---: | ---: |
| ascii4k/unpack | 1 → 1 | 4112 → 4112 | 1 → 1 |
| ascii4k/rpc_decode | 0 → 0 | 0 → 0 | 1 → 1 |
| ascii4k/rpc_decode_manual | 1 → 1 | 4112 → 4112 | 2 → 2 |
| zeros4k/unpack | 2 → 2 | 5150 → 5150 | 1 → 1 |
| zeros4k/rpc_decode | 0 → 0 | 0 → 0 | 1 → 1 |
| zeros4k/rpc_decode_manual | 2 → 2 | 5150 → 5150 | 2 → 2 |

公开路径省略视图的候选，首次全量 zeroRun16x64 中位数约回退 11%；完整热身后同组十项配对复核中，zeroRun8/16/17x64 分别回退约 35%/33%/35%。只恢复公开返回逻辑、保留私有候选后，这三项约 -0.7%/-0.8%/-0.2%。但随后保留私有候选的全量中，多项零段仍回退约 10%–24%，因此私有候选也撤回。这些证据不足以确定 V8 内部原因。复核及失败全量的全部 Unpack 五轮与来源见 [checks.json](checks.json)，不替代最终完整样本。早期整组版本采样更容易混入时间/GC 阶段偏差；最终收紧为逐操作配对，历史失败值仍保留。首次 ASCII 4 KiB Pack 回退约 15%，配对复核约 -2%，保留该波动证据。

公开/manual 的分配与扫描成本仍在。它们不能通过返回实例可变工作区来消除；原生 pdecode/dispatch 已提供同步借用路径，本轮不增加另一套公共 API 或把手工路径改成原生路径来改善排名。

## 未采用的 Pack 候选

四字节压紧的 SWAR mask + 小表/DataView，以及 switch 变体，在大型游戏与整数数组上更慢；输出游标、预加载和短循环变体也没有稳定收益。最终保留原八字节条件写出，只收窄段状态处理。开发期源码和中间样本保存在忽略的 tmp/sproto-round5/，不作为正式基线。
