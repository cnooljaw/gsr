# Pack 普通 word 的四次双字节写出

基线：gosproto `451998ea0dcf6262bdd4ca0ab6c686d0fb738fac`，完整 Git 归档、独立实验模块；生产库与正式 v0.4.0 依赖不变。

本轮没有继续调整 header 公式或摆放。候选保留原位图、header、稀疏/FF/尾块逻辑，把普通 3–7 非零字节路径的八个 byte store 换成四次 LittleEndian.PutUint16。每对先根据第一个字节是否非零选择右移 0 或 8 位，再写到既有 ranks 表示的对起始位置。

## 等价性和边界

对中第一个字节非零时保留原两字节；第一个为零时，第二个字节移到低位。第二个也为零时，该对不贡献返回字节。双字节写入中多出的无效高字节可由后续对覆盖，或位于有效返回长度之后；长度仍由原 ranks 计数决定。每对开始前最多已有 0/2/4/6 个有效字节，因此双字节写入始终落在原固定八字节 payload 范围内，不扩展写出余量。word 在写出前已完整载入，组合工作区的源/目标间隔不变。

这减少了 payload store 次数，却增加了成对选择移位和动态切片长度检查。arm64 静态指令从 296 增为 332，是否有整体收益必须测量，不能按四次写入对八次写入直接推断两倍速度。

## 方法与验证

复用上一轮同模块 sampler，八项：game_small/game_large/int32_edges 的 Pack/PEncode，加固定四/七非零字节 Pack。每项 self、clone、两遍候选；每进程六轮，每轮四个 ABBA/BAAB 四元组。两侧各预热 50ms，基线 256 次校准目标 20ms，等调用数。GOMAXPROCS=1、GOGC=100、GOMEMLIMIT=off。所有原始块、GC、暂停与分配保留，无控制扣减或异常值剔除。本轮没有摆放轮换。

预检包含 3584 组 mask/长度 wire、输入快照、真正共享缓冲后端源区域写入，及已有 TestPack/TestUnpack，开启 race/checkptr；真实 fixture、逐进程 Pack/PEncode wire/cap、harness vet/build 同时验证。源码与二进制计时前后哈希不变。candidate 的逆变换必须还原 clone。完整数据见 ALL-CASES.md、analysis.json、commands.json 和每项原始 JSON。

复现前确认 `/private/tmp/gsr-gosproto-fork` HEAD 等于上述基线：

```sh
python3 docs/benchmarks/2026-10-21-gosproto-pack-pair-store/run.py tmp/新的空目录
python3 docs/benchmarks/2026-10-21-gosproto-pack-pair-store/analyze.py
```

重测会覆盖本报告内样本，需先另存。本轮不落地生产，因此不重复全库、官方 oracle、fuzz 或 Go/TS 集成验收。

## 结果：不采用

| 场景 | 第一遍中位/累计 | 第二遍中位/累计 |
|---|---:|---:|
| 小型 Pack | +35.05% / +30.93% | +34.10% / +35.12% |
| 小型 PEncode | +10.26% / +10.51% | +9.19% / +15.26% |
| 大型 Pack | +44.26% / +41.18% | +45.18% / +44.69% |
| 大型 PEncode | +14.25% / +13.36% | +20.82% / +72.57% |
| 整数数组 Pack | +41.20% / +39.29% | +40.98% / +48.93% |
| 整数数组 PEncode | +19.65% / +19.73% | +21.97% / +25.28% |
| 固定四非零字节 Pack | +58.80% / +71.60% | +57.51% / +54.50% |
| 固定七非零字节 Pack | +59.22% / +61.53% | +58.52% / +59.16% |

正数表示耗时增加。全部八项两遍的中位和累计均退化，控制的偏差量级明显小于上述变化；本轮没有足以保留此改法的性能证据。没有把指令数当唯一判据，也没有设置最小收益门槛。

这证明“本 Go 候选的四次双字节写法”不划算，不证明任何批量写出都不可能有效。新增的依赖移位、切片/长度检查与实际计时退化一致，但没有逐指令 CPU 归因，不能定量声称某一项独占全部代价。大型 PEncode 第二遍累计 +72.57% 与其中位 +20.82% 的分歧保留；不靠删长尾美化结果。

共 32 进程、192 轮、768 个四元组、3072 块，41 条记录命令均成功。正常分配保持：小型 Pack/PEncode 352B/1alloc，大型 Pack 3456B/1alloc、PEncode 3968B/2alloc，整数数组二者 4096B/1alloc。没有把额外分配混入算法性能比较。

后续不在当前路径上继续堆叠可变位移来换取更少 store，也不重复这个候选。生产路径维持原八次 byte store；直接收集位图的小收益候选仍单独保留，不与本轮失败组合。下一轮可回 Body 主线复核实际热点，将 Packing 现有反例作为工程约束，而不是假定较宽写入必然更快。
