# 编码布局连续索引写入

日期：2026-10-18。基线为库 `bdfe1d0`、GSR `bf828b0`，前一轮布局增长及报告均已本地提交，未推送。本轮保留候选，新代码/说明和 GSR 记录未提交。Decode 冻结，正式依赖仍为 v0.4.0；没有新 PB/TS 排名。

结论：在容量策略不变的前提下，复用布局的连续索引写入，改善大型游戏 Encode/PEncode/真实 RPC，所有 70 项分配中位数不变。原生整数数组、手工帧仍有成本或不确定性；不因单项不足某个百分比而丢弃收益，也不宣称所有入口都改善。

## 1. 仅修改 add 的外溢追加

原实现先按 len/cap 判断满载，再 append；显式增长已经保证空间充足，编译器仍为 append 保留了 growslice 后备路径。候选使用 `offset = index - 32` 判断满载，随后安全 reslice 到 `offset+1` 并写入该位置。

调用内不变量与等价证明：

1. 零值 layout 的 count=0、外溢长度=0。前 32 项只写 local。
2. 只有 add 修改 count/外溢长度；set 仅改记录值，next 仅改读游标。因此外溢追加前 `len(extra) = count - 32 = offset`。
3. 满载时 offset=旧长度=旧 cap；零容量分配 128，其后都是至少 128 的 2 次幂，所以 `max(128, offset*2)` 与原零值/倍增规则相同。
4. 写入 offset、长度设为 offset+1、count 增一，继续维持不变量。返回的逻辑索引、晚回填头项及写出消费顺序均相同。

容量序列、栈内 32 项、逐项预算和所有 add 调用点不变。没有按未访问数组长度预分配，没有共享缓冲/缓存/池/新 unsafe。Go 切片和索引检查保留；不依靠删除检查换速度。除 encode.go 外的生产 Go 源码不变，既有测试不改、不新增。

计时前的第一版草稿仍用零容量 if，内联成本 **81>80**；保留 [草稿补丁](preflight-direct-index.patch) 和编译记录。等价 max 规则使固定候选成本为 **76**、保持内联（基线 72）。草稿没有 CPU 采样，不将这个编译选择混入 A/B 或隐藏为成功样本。

## 2. 固定原矩阵与复算

复用上一轮原 43 项 + 9 种布局形态 × Encode/PEncode/RequestEncode+CancelSession，输入与排列不变，共 **70 项**。Go 1.24.13 / darwin arm64 / Apple M2，GOMAXPROCS=1，默认 GC 启用。

self 同函数与 clone 同源独立模块各一次，两个 compare；每项 6 轮 × 4 quartet × 4 ABBA/BAAB 块，10ms 目标。**26880 块、6720 quartet、1680 配对轮**独立复算到 1e−12 一致，同时核对控制标志与分配。所有构建结束后才采样，没有计时重跑或采样中修改源码/计划/探针。

下文百分比是六轮 B/A 比率的中位差，负数为更快；绝对 ns 是每轮几何均值差的中位数。累计 ns/call、全部轮值/控制原样在 [joined.json](joined.json)；不从比较结果扣除控制漂移。计划、驱动、探针和原始结果均随报告保存。

## 5. 成本与不确定性

- 原生 int32 数组纯 Encode **+1.71%/+1.20%（+49/+35 ns）**，累计亦 +1.37%/+1.13%。root 仍经过修改后的 add，成本不能忽略；self 因波动失败，clone 通过。
- 手工 4KiB zero frame **+4.55%/+4.33%（+154/+166 ns）**，第二轮累计却 −2.62%。self/clone 均失败，IQR 34.78/42.98 个百分点；源无变化的 Pack 与新的 root 预检同处该路径，不能强行归因单一环节。
- Echo4KiB 纯 Pack **+15.97%/+17.31%（+95/+93 ns）**。纯 Pack 源码未变，两臂/两轮的 **296 条符号指令完全一致**；self/clone 中位差 −8.70%/−8.76%，IQR 15.58/45.13pp、全部 6 轮中 5% 窗口均为零。具体环境/GC/代码布局原因未确定，不说已解释为噪声，不将它视为此次增长算法本身变慢或删样本。
- Echo4KiB PEncode **+8.15%/−0.45%**、wide64 Encode **−1.97%/+9.44%**，方向翻转；宽整数数组本身不外溢，但 root 经过修改的函数，不能说入口完全未变或宣称确定收益。

控制通过数 **self 40/70、clone 38/70**，完整失败标志保留，作为不确定性而非自动否决或调整公式。四个 >100ms 块保留于 [long-blocks.json](long-blocks.json)：clone zero frame 同一轮的三个 B 块约 229.6/154.7/100.7ms，GC 分别 4/28/29 次；第二轮 game_small PEncode 的 A 块约 113.3ms、3 次 GC。没有删块或挑轮。

## 6. 编译与验证

[编译事实](compiler-facts.json) 来自实际比较二进制与相同源码的 compiler 报告：

| 函数 | 符号指令 | 栈帧 | growslice 后备调用点 | panic 检查调用点 |
|---|---:|---:|---:|---:|
| encodedIntegerRecordSize | 276→256 | **144→112 B** | 1→0 | 4→6 |
| encodedSize | 552→532 | 272→272 B | 1→0 | 5→7 |
| packInto | 296→296 | 112→112 B | 0→0 | 13→13 |

两个预检 helper 的 append 后备路径消除，整数记录 helper 帧减少 32B；通用帧没有缩小。安全切片/索引检查调用点反而增加，未移除边界检查。AST 内联成本 72→76 是编译器启发值，不能等同机器指令或耗时；指令减少本身也不是速度证明。

实际通过：

- 固定候选复用 4 项既有当前值/旧输出/预算回归；计时前草稿的 7 项检查也保留，不冒充固定候选的 CPU 证据。没有新增测试函数或修改已有测试。
- 隔离 harness **109 形态 / 525 项** raw/packed/三种真实 RPC/ErrLimit 的 wire、返回 cap、独占与错误差分，harness 统计/选择/fixture/vet 检查通过。
- 固定四组采样、独立复算、编译输入/输出核对，fresh prepare-only 归档的核心指纹一致；只重建、不重计时。
- 官方 C/Lua/header/shared-object SHA 逐个重新核对；库全测（启用官方 oracle）、全库 race/checkptr、vet 通过。
- 两项有限 10s fuzz 均 PASS：Pack **9053** 次，3s 后计数停增、约 11s 返回；Codec **475186** 次。Pack 覆盖有限、原因未定，不重复跑来补数。
- 临时 modfile 指向工作库的 GSR 三包与 Go/TS **7/7、零跳过**通过，含 Plain/MAC。正式 go.mod/go.sum 未变。

输出见 [acceptance.json](acceptance.json)、[targeted-checks.json](targeted-checks.json) 和完整 commands。未跑 GSR 全仓/race、跨平台、PB/TS 新 timing，也未重复未改 Pack 的 17984 独立差分。

## 7. 决策及后续

保留连续索引候选：大型主要业务入口与多种长数组的实际增量明确，分配/容量不变，生产改动局部且可由调用内不变量解释。接受公开的小成本与不确定性，不设最小收益比例，也不计算掩盖差异的“综合胜率”。新代码和文档未提交、未推送。

下一轮先只读刷新当前 Encode/EncodePacked/RPC 的 CPU 与分配 profile，并单独核对反复出现的未改 4KiB Pack/手工帧波动。新诊断不能替代本轮或历史比较，不能重跑到控制通过；据明确热点再选生产候选。Decode 继续冻结，不扩大 unsafe 或改容量/owner/预算。
