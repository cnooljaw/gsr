# 真实高频 mask 对照与连续源候选收尾

2026-10-20，基线 gosproto `5360fe0`，继续使用同一个连续源窗口候选，适配函数与前两轮逐字节相同。**真实高频的4～6字节mask单独重复时也有收益，但原始业务流仍明显退化。有效位位置不是足以解释或修复问题的单一因素，继续拒绝通用替换。** 本轮结束围绕此候选补固定mask对照，不再据局部正向堆密度分流。

上一轮报告已提交 GSR `0a5eded`，未推送。独立库仍5360fe0及原六项用户删除；正式依赖v0.4.0不变。本轮诊断与文档留审查、尚未提交，没有新生产实现或PB/TS排名。

## 对照与结果

选取原消息高频mask：0x11、0x21（2有效字节）；0xd1、0x99、0x1d、0xe2（4）；0xc7（5）；0x9f、0xf9、0x7e、0xfc（6）。每种word重复512次，非零位置填bit序号+1，其他位置为零；与相同有效字节数的低位连续mask对照。mask-map.json记录位置及来自已提交wire审计的原消息频次，不把“高频”凭印象指定。

每个合成输入在计时前通过Pack和独立构造的完整plain字节核对，基线/候选结果、cap及输入不变均检查。原始game_large/int32_edges另测Unpack和组合解码，语义与原夹具不变。单一重复word与真实消息是不同负载，不把前者替换成业务验收。

共14项中位/累计反向，全部GC、暂停、长尾和分配保留。FF控制次轮累计+99.81%没有删除，也不把它归因于未改变的FF算法。实际块约1.55～451.22ms，校准目标20ms不等于实际块长；最大堆快照53,815,112B不是峰值。

## 补充 CPU profile

在采样结束后另建独立harness副本，同一二进制通过共同函数变量选择baseline/candidate，仅采原始两消息的Unpack，各约2秒，共4个独立CPU进程、21条构建/核对/导出流程命令。没有修改计时二进制或其harness，未把profile计时合并进前面的配对数据。

这些百分比各有独立分母，GC/kevent和运行次数不同，不能把74.09%→60.59%称作提速，或直接相减认定省了多少时间。所有运行时样本保留，不按“有效CPU”重新归一化。带profile的ns/op也不作新排名。

大型候选第二遍计数行累计采中50ms、range窗口/循环行100ms、写出行330ms（完整样本2.36s）；整数数组相应50/110/340ms（2.07s）。预检的读取、分类、预算与推进也继续占明显样本。新增计数/控制不是零成本，但行级采样可能覆盖邻接指令，不能将这几个数字加减旧profile就宣称定位了全部13%退化。profile源码映射和完整分母保存在profiles/，证据只支持成本仍分布在多处。

汇编同前：源索引静态检查4→3、切片检查10→12、机器字行388→396、栈112B不变。普通循环减少一种检查并未减少总静态成本；正确性与安全证明成立不等于该实现更快。

## 后续取舍

连续源窗口候选的局部正向已经充分保留，但三轮原消息Unpack均明显反向，不能再用固定word结果作通用替换理由。停止继续补同类固定mask表格，不宣称已证明“bit位置无影响”或“全是分支预测”。

下一切片保留已采用的mask清位写出循环，单独评估首遍预检的普通mask分支：让常见单word长度计算、输入边界和预算推进更直接，零段与FF保留各自处理。完整首遍、错误优先级、精确分配、cap和ownership都不能删；先看编译结果，再用既有全mask/坏包/预算回归核对及真实Unpack/组合路径测量。此方案本轮尚未实现，也不预告收益。Body Decode继续开放，不能因这条Packing候选失败冻结另一主线。
