# Pack 小幅收益复评与组合保留

2026-10-17，GSR 基线 b2b3dd7、gosproto 基线 bba3326。按用户裁决取消最低收益百分比，重新评估稀疏 word 展开与 FF 段集中处理。**本轮保留两项组合到 gosproto 工作树，未提交或发布。** GSR 依赖仍为 v0.4.0，Decode 继续冻结。

## 修正判断标准

此前“Pack 至少快 5%、PEncode 至少快 2%”把筛选目标变成了价值边界；稀疏候选 Pack −4.77%/PEncode −2.65% 仍被排除，就是一个不合理的结果。对应历史原值和当时判断保留在 [原复测](../2026-10-17-gosproto-pair-calibration/RESULTS.md) 与 [FF 段实验](../2026-10-17-gosproto-pack-runs/RESULTS.md)，本报告给出后续重新裁决。

现在分别考虑收益幅度、证据可信度、业务路径、分配/回退和维护成本。简单局部修改可以保留小幅改善；测量控制异常表示证据待确认，不等于候选没有价值。仍要求官方 wire、输入不变、输出独占/容量、预算和失败行为不变，不删除不利样本或反复运行挑选最好结果。完整原则写入 [RFC 性能验收](../../RFC-GOSPROTO-PERFORMANCE.md#4-验证与验收)。

## 固定实验

在计时前写入 [plan.json](plan.json)：原 19 项业务 Encode/Pack/PEncode 与完整 Echo 帧；候选分别为 sparse、ff-runs、combined。两轮顺序为 sparse→ff-runs→combined、combined→ff-runs→sparse，开始和结束各测 self/clone。默认 10 ms、六轮、每轮四组 ABBA/BAAB 不变，共十次业务运行。

随后按同一计划各测一次 19 种合成形态：32 B/4 KiB 的零至八非零字节密度、FF 六/七字节合并、2047/2048/2049 B 边界、早遇零及零段交替。复用原 packPatterns 输入和同一计时模板，未按业务结果调整形态或参数。

Apple M2、Go 1.24.13、GOMAXPROCS=1、GC 开启。共 **23712 个块、5928 个四元组、1482 个配对轮次**，全部保留并独立复算一致。具体来源、命令、四类控制和两轮数据见 [joined.json](joined.json)、各运行目录以及 [validation.json](validation.json)。没有新测 PB 或 TS 性能，不产生新的四实现排名。

## 分别复测

下表是各次运行内配对 B/A−1 的六轮中位数，负数更快。两轮独立报告，不挑最好一轮，也不将不同版本的最好值拼接：

| 候选 | 大型 Pack：轮 1 / 轮 2 | 大型 PEncode：轮 1 / 轮 2 | 整数数组 Pack：轮 1 / 轮 2 | 整数数组 PEncode：轮 1 / 轮 2 |
| --- | ---: | ---: | ---: | ---: |
| 稀疏展开 | −3.78% / −4.22% | −2.24% / −2.22% | −5.14% / −5.56% | −2.59% / −2.93% |
| FF 段分离 | −1.83% / −3.99% | −3.32% / −2.95% | −1.66% / −1.25% | +0.54% / −0.76% |
| 两项组合 | −5.29% / −4.21% | −3.72% / −4.24% | −4.56% / −5.87% | −2.83% / −3.04% |

稀疏展开在两轮都带来业务组合改善，值得保留。FF 分离对整数数组组合基本持平，但大型、小型和零字节路径有价值，不能要求它在每个场景都单独超过固定幅度。组合收益也不是两项百分比相加，必须直接测量。

## 组合的业务效果

| 路径 | 第一轮 | 第二轮 |
| --- | ---: | ---: |
| AddressBook PEncode | −2.47% | −2.01% |
| 小型游戏 PEncode | −3.84% | −4.27% |
| 大型游戏 PEncode | −3.72% | −4.24% |
| 896 项整数数组 PEncode | −2.83% | −3.04% |
| ASCII 4 KiB body PEncode | +0.79% | −0.85% |
| ASCII 32 B 完整帧 | −3.29% | −4.06% |
| UTF-8 完整帧 | −0.65% | −0.56% |
| ASCII 4 KiB 完整帧 | +1.10% | −1.14% |
| 零字节 4 KiB 完整帧 | −19.58% | −20.32% |

大型 PEncode 与零字节帧十二轮均更快，整数数组和 ASCII 32 B 帧为十一轮。ASCII 4 KiB 的正负小幅变化视为基本持平，UTF-8 的亚百分比改善也不宣称已被精确分辨。两轮组合的冻结 Encode 控制仍有约 −1.93%～+0.39% 差值，不能将每一个百分点都归因于 Pack。

四组原工具总控制通过数分别为 12/19、13/19、9/19、13/19；它们的逐轮离散、分配原值与失败标记均保留，没有事后改成通过。本轮保留判断依赖两轮反向顺序、多个实际路径的方向一致、字节形态中的机制表现、简单实现和完整正确性验收；不以某一个控制布尔值自动批准或否决，也不将这些描述性结果称为统计置信区间。

## 代价与分配

合成输入中，组合版 4 KiB 每 word 恰四个非零字节的形态慢 **3.33%**，IQR 0.57 pp；该形态约 3 μs，代价约 0.1 μs。它是需要披露的局部损失。两轮真实大型/整数数组、小型和完整短帧均有改善，故本轮接受这项权衡；没有因合成回退机械放弃全部业务收益。

19 个形态中，其余较明显的正向值为 FF 2048 B +2.17%、IQR 2.58 pp，幅度尚不足以确认持续回退；32 B 各密度都未出现中位数回退。纯零/单/双字节 4 KiB 分别约 −33.69%/−29.70%/−36.40%，FF 后接六/七非零字节段约 −7.40%/−7.78%。这些只是分布说明，不能替代真实组合测量。

所有普通业务的 B/op、对象数一致，Pack 输出容量公式未变。完整帧的部分分配窗口仍相差 16 B/128 调用，即 0.125 B/op：两轮零字节帧的差值方向相反，对象数均为 5；第一轮 ASCII 帧也出现同量级差值。结合此前 [tiny/GC 机制探针](../2026-10-17-gosproto-pair-resolution/RESULTS.md)、当前相同输出容量、独占检查和源码路径，未发现新增对象或分配策略变化。原始计数不截断，也不把该边界现象直接描述为实现新增内存。

## 实现与维护成本

保留的源码与两轮 combined 和形态采样逐字节一致，仅 pack.go 生产文件改变；另更新库 CHANGES。Decode、Unpack、Encode、RPC、limits、meta 及 TS 均未改。

普通 word 循环不再维护 FF 的三个跨迭代状态；遇到完整 FF 起点才由私有 ffRunBytes 扫描，沿用六/七字节合并、256-word 上限、长非零搜索和尾部补零。至多两个非零字节的路径使用最多两次固定位置提取。没有增加 public API、解析器、表、池、unsafe 或第三方依赖。生产文件净减七行，但保留理由是路径清楚且有实际收益，不是行数本身。

## 正确性与接线验收

- 三个候选分别通过既有 Pack/零段/FF 尾块/解包预算用例及 17984 组旧新差分；复用原探针，额外检查输出 cap 相同。没有为已有外部契约再新建一套生产测试。
- 保留的真实工作树通过完整库 race + 严格 checkptr、vet，启用固定官方 C/Lua 对照；官方源码与模块指纹核对一致。
- Pack/Codec 各约十秒有限 fuzz 通过，615 / 261602 次执行。Pack 后段报告零新增执行并正常退出，保留完整输出，没有延长或重跑；有限 fuzz 不代表穷尽。
- 临时 modfile 下 GSR Sproto、debugserver、Benchmark 三包通过，TS 构建及 Go/TS Plain/MAC 集成 7/7、零跳过。正式 go.mod 未变。
- 十个 prepare-only 归档与三个候选检查副本精确重建来源；所有原始比值独立复算一致。没有重跑 GSR 全仓/race、TS 性能或跨平台运行。

[acceptance.json](acceptance.json) 保存验收命令、输出与耗时。未执行 commit、push、tag 或发布，两个仓库的本轮改动留待审查。

## 其他历史候选如何处理

| 历史候选 | 重新定位 |
| --- | --- |
| 稀疏展开、FF 段分离 | 本轮分别复测并保留组合，旧最低百分比不再是撤回理由。 |
| 连续零 word Pack 批处理 | 旧记录有明显零块收益，也有其他路径回退/噪声；列为待复核，不能仅因小幅数值代价自动否决。当前组合已改善零块，未来须与新基线比较。 |
| 普通 Unpack 源游标 | 旧记录有整数数组 PDecode −4.1% 和单字节形态 +12%；应重新辨别实际回退与环境波动，不能只写“组合收益小”。本轮未恢复。 |
| 第二套整数叶子 parser | 维护两套解析逻辑是真实成本，仍须权衡；此前 −1.3% 不能单独作为否决理由。遵守 Decode 冻结，本轮仅记录。 |

这不是将所有旧候选直接混合，而是逐项保留证据、评估代价，再验证实际组合；本轮只落实上述两个 Pack 候选。

## 复现

```sh
python3 docs/benchmarks/2026-10-17-gosproto-pack-reassessment/reproduce.py \
  --library /path/to/gosproto --output /tmp/gsr-pack-reassessment-business
python3 docs/benchmarks/2026-10-17-gosproto-pack-reassessment/patterns.py \
  --business /tmp/gsr-pack-reassessment-business --output /tmp/gsr-pack-reassessment-patterns
```

输出目录必须不存在。第一个入口可加 --prepare-only，仅重建归档；第二个运行固定形态。历史复现需使用本报告版本的工具、夹具、生成类型和补丁，其指纹保存在各 inputs.json 与 driver-inputs.json。不会修改传入库，不保证重现相同耗时。完整源差异见 [patches](patches/)，实际验收使用的工作树源码指纹见 validation.json。
