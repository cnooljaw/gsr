# 相同 packed 输入的容量、对齐与调用上下文诊断

2026-10-19。上一轮预检位置游标实验已本地提交为GSR `71d313d`，未推送，库仍为af9169d。本轮不重复原70项来择优采用，也不改生产代码；仅沿用已拒绝的同一位置游标补丁，控制源输入，区分反向结果是否来自字节、容量、对齐或调用上下文。该候选状态仍为未采用，新诊断未提交，Decode继续开放。

## 固定40项

从原70项构造/语义检查开始，随后仅保活选中的诊断闭包。选大型游戏、4字节整数数组、8字节整数数组的Unpack/PDecode，以及单字节word、双字节word、FF接稀疏、短零段的纯Unpack，共七份raw/packed字节。每份分四个变体：源首地址模64为0/1，cap等于len/len+64；三种业务消息各8入口、四种形态各4入口，合计40项。

每个变体的A/B闭包捕获同一个wire切片；业务Unpack/PDecode在构造时也捕获同一个wire。不同入口仍用独立进程采样，并不是跨进程共享同一个物理地址。两个cap变体共享同一段首地址，两个对齐段使用同一较大backing中的不重叠副本、各自内容相同；尾部填0xa5，不属于有效输入。原始字节与packed SHA、len/cap、实际对齐和零/FF/普通word分类逐进程保存，160条记录全部核对，见[wire-metadata](wire-metadata.json)及[七份输入](wire-samples.json)。

对齐探针只在初始化中从reflect.Pointer读取uintptr计算切片偏移，没有转回指针或解引用地址，不进入生产库。所选wire的backing保留两个副本和尾部，这是诊断源数据成本，发生在计时前；PDecode仍保留自身构造/解码结果/GC成本，不强行使其等同于纯Unpack。metadata只保留hash/整数等，不通过它保活全部输入；不复用输出或目标对象。元数据在构造时采集，本轮固定Go1.24.13 darwin/arm64。

self/clone/两轮compare共160独立进程、15,360块、3,840四元组、960轮、640快照。GOMAXPROCS1、GOGC100、无限GOMEMLIMIT，清三个sink、GC/50ms预热、原校准/10ms块、每侧3×128次分配观察保持。所有构建/测试/vet/汇编先于第一块计时；冻结矩阵和源码，不重采、删样、扣控制或按最佳变体更新生产实现。

## 结果与可得结论

下表范围覆盖该样本四种变体、两轮共8个配对中位数；负值更快。它不是置信区间或选择最佳的优化数据。[完整40项](ALL-CASES.md)含每一项的累计差值和控制：

| 输入 | 纯Unpack变化范围 | PDecode变化范围 |
| --- | ---: | ---: |
| game_large | -13.36%～-11.51% | -6.91%～-1.83% |
| int32_edges | -13.90%～-11.60% | -11.18%～-8.17% |
| width8_len896 | -9.32%～-8.23% | -9.51%～-5.60% |
| nonzero1x256 | +30.19%～+36.65% | — |
| nonzero2x256 | +17.37%～+43.09% | — |
| FF512-sparse4096 | +7.14%～+12.84% | — |
| zeroRun8x64 | -3.50%～+2.27% | — |

三种业务消息的纯Unpack与PDecode共48个compare中位数均更快；单/双字节word和FF接稀疏的24个中位数均更慢，短零段方向混合。相同源字节下，这四种对齐/cap设置没有把业务/普通形态的方向翻转；业务纯Unpack本身更快，不支持把PDecode收益全部归到额外Decode调用。源对齐、额外容量或额外Decode调用不足以单独解释原反向；这不是证明它们在所有环境中完全没有影响。

依然不能据此确认CPU cache、分支预测、哪条指令或预检/恢复哪个阶段为唯一原因。这个诊断没有覆盖所有字节分布、全部偏移、运行时或硬件，也没有同时控制两个入口的所有对象构造/GC成本。原位置游标不因这份结果改变未采用状态。

## 机器码核对

独立按反向CBNZW目标提取普通mask内循环：起点MOVD到回跳含16条机器指令。原70项的当前/位置游标版本，以及本轮四模式的这16个机器字逐字相同；原70项两个canonical版本的循环起点绝对地址相差20字节。[restore-loop](restore-loop.json)记录精确范围、机器字/SHA、入口内偏移和地址模64，不能把它扩张为“整个恢复阶段机器码完全相同”。

地址变化是实际证据，不是cache/预测器根因证明。函数其余预检、后置源切片、寄存器分配和链接上下文仍可能不同；没有向生产代码插NOP、对齐填充、noinline或特定mask提示。下一独立[分函数实验](../2026-10-19-gosproto-unpack-size-phase/RESULTS.md)只提取原始完整预检，用来检查阶段耦合和调用成本，不携带位置游标。
