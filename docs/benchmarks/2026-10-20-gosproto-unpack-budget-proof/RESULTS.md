## 证明及边界

入口在拒绝无效maxBytes后，计算`len(src) <= maxBytes/8`，避免`8*len(src)`本身溢出。每个已验证packed段都满足产出不超过输入字节数的8倍：

- 零mask或连续零mask：每1个输入字节产出8字节，是最紧上界。
- 普通mask：输入1+有效字节数，产出8字节。
- FF：输入2+连续原始字节数，产出该原始字节数。

因此每个完整、已验证前缀的产出之和不超过`8*len(src) <= maxBytes <= MaxInt`，预算与尺寸累加均安全。FF声明长度仍必须先核对输入实际长度，不能把坏包声明的产出直接加入size。证明不成立时仍需逐段原预算检查；证明成立也不能跳过任何段的输入边界验证。

严格预算路径的原错误顺序保留：先验证当前段边界，再判断本段产出预算；此前完整前缀已经超预算时，仍先返回其ErrLimit，不继续读取坏尾部。输出在完整首遍后精确分配，cap、独占结果、零段/FF及第二遍写出均不变。无新API、unsafe、池或输出复用。

## 共享循环版

取消私有扫描helper，只在原循环加入一次证明与最终预算判断的条件：

```go
budgetProved := len(src) <= maxBytes/8
// 原完整段解析和输入检查
if !budgetProved && produced > maxBytes-size {
    return nil, ErrLimit
}
```

零段原有的有界扫描和预算检查也保留，并非所有检查都被旁路。证明不成立时执行原预算判断；代价是在共用热循环里增加条件分支。机器字行388→392、栈112B不变，静态panicIndex4/panicSlice*10不变，没有运行时helper。第二遍写出源码两版均与基线完全相同，但编译布局仍可能变化。

新增3种原始消息×Unpack/组合路径的精确预算对照，预算等于实际解包长度。对这些输入，该预算小于8倍packed长度，因而强制证明失败，测量严格回退。原输入和wire不变。

负值为候选耗时更低，中位和累计总时间/调用数并列；全部27入口及self/clone见 [ALL-CASES.md](ALL-CASES.md)。
