# 同二进制静态编码调用树复核

2026-10-21，基线gosproto `2e1d44b`、布局分段候选 `451998e`。前轮正常入口报告已提交GSR `a818d26`，未推送。本轮实现并验证静态调用树：**内部选择器导致的额外布局分配已消除，但同源码控制偏差仍在，不能确定候选的精确提速幅度。** 没有新增生产改动。

## 静态路径

在同一个完整基线归档中复制三条路径：顶层Encode入口、buffer、message、field、整数记录写出（候选另含数组helper）。每条路径的内部调用都是直接调用；layout只在buffer函数内部创建，不作为参数穿过可变函数指针。

基线与clone来自同一个2e1d44b源码，候选写出来自451998e。资源预检、schema/cache、消息对象和公共scalar/Pack等未改部分共享。计时闭包只在最外层选择固定入口，然后直接运行该静态树。既有三模式契约测试另有最外层选择器，只接收message/limits/pack/prefix，不接收layout；计时闭包不依赖它。

另保留一个未包装的正常入口参考，直接使用原始buffer/write路径。分配对照先确认所有静态树与该参考数量相同。逐函数名可逆替换核对原始源码，gofmt后再次还原、去注释/空白逐体核对通过；没有在复制中偷偷删掉检查或修改循环。

## 分配与机器码

计时前AllocsPerRun对5条代表消息的Encode/PEncode，逐一检查未包装正常参考、基线、clone、候选分配次数一致。块内实际记录也确认：

| 消息 | 两轮基线/候选Encode与PEncode的中位B/op / allocs |
| --- | ---: |
| AddressBook | 144 / 1 |
| 大型 | 3968 / 2 |
| 整数数组 | 4096 / 1 |

没有旧内部选择器实验的4144B/3allocs，也没有用池化/共享buffer/关闭GC实现这一结果。累计尾数仍完整保存，不保证每个块绝无测量附带分配。

基线/clone的Buffer/Message/Field/Record静态指令行数分别同为240/544/912/216，栈分别同为416/224/224/32B。仅将树函数名称归一化后，Record汇编摘要一致，其余函数摘要不同；地址相关操作数也会自然随函数位置变化，不能直接把摘要不同等同于算法不同或将偏差全部归给某个地址。

这次共享schema与同一输入并保持正常分配，排除了前轮的额外布局分配及部分跨进程差异，仍未排除代码位置/调用环境、CPU状态和GC/调度等影响。当前尚无单一根因结论。

GOMAXPROCS1/GOGC100/GOMEMLIMIToff，每臂50ms预热，基线256次校准20ms目标块；候选实际块6.842～225.550ms，全部保留，不按块长/GC过滤。所有输入和产物均在计时前构建。

没有新生产变更，不重跑全库/fuzz/oracle/GoTS，451998e的完整验收继续有效。真实库七项用户删除不动，正式依赖仍v0.4.0，未推送或发布。复制树和最外层测试入口仅在临时归档，不成为公共API。
