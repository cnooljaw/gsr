# 同函数 A/A 的墙钟与进程 CPU 诊断

2026-10-17。上一轮 GC 边界诊断与工具改动已本地提交为 GSR `3a88564`，未推送。本轮只在独立归档增加 macOS 诊断探针，正式 gosproto 保持 `bba3326` 且工作树干净；GSR 依赖仍为 v0.4.0，Decode 继续阶段性冻结。

**三项同函数 A/A 的墙钟计时均未通过原计时门槛，进程 CPU 计时均满足相同的数值门槛。** 本轮能确认墙钟波动中存在显著的执行之外等待成分，但不能确定具体责任方，也没有建立新的优化验收基线。

## 固定实验

计时前写入 [plan.json](plan.json)：仅运行一次 self，选择大型 Pack、整数数组 Pack、4 KiB ASCII 完整帧三项，六轮、每轮四组 ABBA/BAAB，每块目标 40 ms。保留全部 288 个块、72 个四元组与 18 个配对轮次，没有重试、筛掉 GC 块或搜索参数。

Apple M2、Go 1.24.13、GOMAXPROCS=1、GC 开启。每项预热前显式 GC 一次，交错预热 50 ms；两边使用相同函数值、相同捕获变量和相同调用次数，输出写入原 sink。实际诊断约 12.35 秒，在原 90 秒上限内完成。

隔离 [探针](cpu-probe.go.txt) 在 time.Now/Time.Since 区间外调用 syscall.Getrusage(RUSAGE_SELF)，保留 user/system CPU 各自的增量，分析时求和。GC 周期观测也在墙钟区间外，继续保留所有含 GC 的块。

进程 CPU 包含 Go Runtime、GC 和其他线程的执行时间；它不是业务 goroutine 的独占 CPU。CPU 观测窗口略宽于墙钟窗口，系统调用本身也有成本，不能把两者之差精确等同于某类等待时间。GOMAXPROCS=1 也不保证进程 CPU 必然小于墙钟；探针没有截断或强制该关系。Go 的 syscall 类型、常量及包装实现版本指纹见 [validation.json](validation.json)。该探针仅验证 macOS，不进入通用配对工具或生产代码。

## 结果

差值为配对 B/A−1；IQR 为六个轮次比值的离散程度，不是置信区间。以下“满足”只检查原计时数值要求：中位差绝对值 ≤2%、IQR ≤3 个百分点、至少五轮差值绝对值 ≤5%。**本轮未测分配，也未做 clone，不能称为总控制通过。** [summary.json](summary.json) 的 controlAccepted 均为 null。

| 项目 | 墙钟中位差 / IQR | 墙钟五个百分点内轮数 | 进程 CPU 中位差 / IQR | CPU 五个百分点内轮数 |
| --- | ---: | ---: | ---: | ---: |
| 大型 Pack | +0.42% / 9.57 pp | 4/6 | +0.38% / 2.06 pp | 6/6 |

全部 288 个块均观测到完成 GC，但 CPU 计时仍比墙钟更稳定。因此不能仅用 GC 周期数解释墙钟极值；同样不能据此认定 GC 没有成本。系统调度、进程或 Runtime 等待、其他负载及观测影响尚未分离；CPU 计时也无法消除频率、核心迁移或缓存状态对执行速度的影响。本轮没有采集足以归因这些因素的系统调度证据。

## 结论与后续边界

继续拉长块或微调统计参数的收益已经很低，本轮不再追加这类试验。进程 CPU 可用于后续 profile 和候选机制的交叉检查，不能替换墙钟门槛；ASCII CPU 单轮仍有约 ±4% 的偏移，也不能把满足一次数值门槛当成所有小幅收益都可分辨。

下一轮回到 Pack 的实际成本，优先寻找足以超过当前噪声的结构性改进。任何候选仍须满足原正确性、资源、Pack/PEncode 收益及回退要求，并在可通过 self/clone 的墙钟条件下确认；本轮未重新启用稀疏写出候选，没有新的 PB/SP 排名或生产优化。
