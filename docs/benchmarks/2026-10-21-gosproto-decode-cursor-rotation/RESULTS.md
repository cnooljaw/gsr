# Decode header 游标：大型消息的延长块与实际摆放轮换

基线为 gosproto `9048cfa`。候选与前轮完全相同：整数记录 header 按两字节游标遍历，内容游标、检查、预算、字段查找与独立对象分配不变。此次没有新算法或生产变更。

## 控制

只测game_large的Decode/PDecode，目标块从前轮20ms提高到40ms；它是校准目标，不保证每块实际耗时恰为40ms。每进程六轮、每轮四组ABBA/BAAB，双侧50ms预热，基线256次校准，两侧等调用数；全部块、GC、暂停、分配和长尾保留。GOMAXPROCS=1、GOGC=100、GOMEMLIMIT=off。

三个二进制各包含baseline/clone/candidate，依次按012、120、201轮换定义。实际相对地址在计时前检查：

| 布局 | baseline | clone | candidate |
|---|---:|---:|---:|
| 012 | 0 | 1584 | 3168 |
| 120 | 3152 | 0 | 1584 |
| 201 | 1568 | 3152 | 0 |

候选符号略短，因此相邻偏移不全相等。只确认代码位置改变，不据此指定硬件根因。定义内容跨布局相同，clone与基线相同，候选逆变换还原基线。caller和defer相关代码的所有位置没有逐项独立控制，因此不能宣称排除了全部布局影响。

三个布局的构建、差分/race/checkptr、fixture/vet与两个真实入口预检全部先完成，再按mode、入口交错布局计时。self/clone/两遍候选都保留；不减控制，不把布局池化为一个“校正收益”。逐布局完整结果见子目录ALL-CASES.md，汇总见ALL-LAYOUTS.md。

## 结果及限制

| 布局 | Decode 两遍中位 | PDecode 两遍中位 |
|---|---:|---:|
| 012 | −1.09% / −2.67% | −0.56% / +3.61% |
| 120 | −2.76% / −1.61% | +1.54% / −1.17% |
| 201 | −1.40% / +1.25% | −0.58% / −0.55% |

负值为耗时下降。Decode六次中位有五次改善，累计有三次改善；PDecode六次中位有四次改善，累计仅两次改善。候选保留，暂不修改生产；不是按百分比门槛舍弃，而是整体组合收益尚未稳定。局部正面信号和所有中位/累计反向均完整保留。

控制仍有明显波动：Decode clone中位012/120/201为−2.25%/−1.08%/+0.06%，对应IQR5.71/4.64/9.63pp；PDecode clone IQR8.17/3.69/3.23pp。没有对照扣减或断言摆放是唯一原因。

40ms校准目标未在所有进程达到：2304块的整体中位39.096ms，192块低于20ms，837块至少40ms；各进程块中位4.092～43.301ms，全部块3.268～413.141ms。因此本次多数块延长，但不能写成“所有块都至少40ms”。原先256次单批校准仍会受短时波动影响，不能借目标时长虚构严格的长块控制。未来若改变校准，应预先定义多批规则并单独验证，不能选掉慢块或选择性重测有利入口。本轮不继续盲目重跑。

24个计时进程、144轮、576个四元组、2304块；36条准备和24条测量、3条独立分析全部通过。driverCommands中另有3条准备脚本调用，不能重复累计为底层准备数量。三布局正常分配保持：大型Decode10416B/532alloc、PDecode13872B/533alloc，精确遥测尾数保留。

初次Python驱动错误不计为成功的计时运行，错误与恢复过程单独记录。最终脚本另增加“已有任何计时样本就拒绝--resume”护栏，以及复用二进制前的源码/二进制哈希检查；这些只影响恢复前验证，没有修改本次计时Go源码或原始样本。
