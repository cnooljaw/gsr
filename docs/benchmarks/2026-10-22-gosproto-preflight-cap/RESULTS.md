# Unpack预检收紧临时切片容量（未采用）

2026-10-22。前轮成本诊断已本地提交GSR `2d95255`，未推送。当前gosproto仍为 `92a155a`。本轮只在正常Git归档的隔离副本实验，不修改生产库，十项用户删除和正式依赖v0.4.0保持。

## 修改与机器码

仅把预检循环初始化从 `remaining := src` 改为 `remaining := src[:len(src):len(src)]`。临时切片不能访问长度以外的容量，而原算法本来就只在有效长度内扫描。完整边界、预算、错误先后、尺寸累加、零段/FF处理、make及恢复循环逐字不变；不是缩减校验，也不改变返回结果的cap。

同一实验二进制中保留原函数作对照。ARM64预检循环少维护独立cap状态，objdump条目原420、候选416，栈帧仍144B。静态条目含编译布局，不等同每次调用少四条指令，也不据此预告收益。见 [原函数](ExperimentUnpackOriginal-objdump.txt)、[候选](UnpackWithLimit-objdump.txt)。

## 实测结果

M2、Go1.24.13、GOMAXPROCS1/GOGC100。11项×self/两遍候选共33进程、3168交错时间块；同模块/同进程ABBA与BAAB，所有GC、尾差和分配数据保留，自对照不相减。完整数据见 [SUMMARY](SUMMARY.md)。负值是耗时降低：

| 项目 | 第一遍中位 / 累计 | 第二遍中位 / 累计 |
| --- | ---: | ---: |
| 整数数组Unpack | +0.72% / +3.90% | −0.26% / −3.64% |
| 整数数组PDecode | +1.14% / +2.10% | +0.95% / −4.50% |
| 大型游戏Unpack | +3.71% / +3.47% | −0.80% / −2.48% |
| 大型游戏PDecode | −0.03% / −1.74% | −4.25% / −9.27% |
| 6非零字节word | +20.10% / +21.34% | +10.86% / +10.58% |
| 7非零字节word | +10.94% / +14.34% | +14.03% / +13.64% |
| 1非零字节word | −12.37% / −11.02% | −6.89% / −4.36% |
| 零32B | −0.97% / −1.54% | −4.32% / −43.46% |
| AddressBook Unpack | +0.66% / +0.84% | +1.18% / +6.34% |

| ASCII4KiB Unpack | +5.55% / +4.63% | −2.92% / −2.22% |

稀疏word确有重复收益，大型组合也有改善，均保留；但整数数组目标路径未确认收益，高密度word两遍明显退化，故不采用通用替换。不是因收益小于某个门槛而舍弃，也没有拿自对照扣出校正结果。不能仅凭寄存器/地址变化确定退化的硬件原因。

self的7非零word中位也有−7.15%偏差，其他控制与累计反向见完整表。校准336批，时间块最小1.575ms、中位57.058ms、最大239.714ms；571块低于20ms、916块低于40ms，迭代上限导致部分小包未满足校准下限。零32B累计−43.46%明显受尾差影响，不当成稳定业务收益。未删除这些块或重跑择优。复算见 [calibration-validation.json](calibration-validation.json)。

PDecode隔离项是在同一结果构造方式下组合Unpack与Decode，不冒充新一轮正式公开DecodePacked/PB排名。本轮没有重测PB或TS；生产未应用候选，因此没有发布版提速结论。

## 正确性、来源与复现

[comparison.go.txt](comparison.go.txt)对全部256 mask、每个截断位置、12种预算检查结果/错误一致、nil语义、精确cap及源不变，输入带3字节偏移及额外容量；另4096个变异包×6预算。差分在native及purego下均使用race/checkptr；完整候选库带官方C/Lua oracle通过。复用已有全mask/保护页/混合wire回归，不新增无行为变化的永久测试。

主流程39条命令及补充2条测试成功，见 [commands](commands.json)、[extra-commands](extra-commands.json)；另保存两份静态objdump。fixture验证、Go+汇编+harness源码及实际二进制的前后指纹核对完成，[plan](plan.json)、[validation](validation.json)可复查。最初手工准备命令曾因工作目录多写一层tmp失败且没有进入测量，修正工作目录后才建立候选；该尝试不计入39条测量流程。

复现：运行 `python3 docs/benchmarks/2026-10-22-gosproto-preflight-cap/run.py <新的隔离输出目录>`，随后运行本目录analyze.py与check-calibration.py。完整基线来自库92a155a，不依赖用户当前删除文件的工作树。

后续不继续堆叠同类cap提示。预检仍是合理目标，但需要直接降低普通word的控制依赖，并保留逐帧边界及预算错误顺序；修改预检和向量恢复应分开验证，不能把正文已领先的数值解码重写来掩盖Unpack成本。本轮新实验报告留审查、未提交。
