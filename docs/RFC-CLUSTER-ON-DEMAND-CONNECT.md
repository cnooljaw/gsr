# Cluster 按需建连与连接恢复

状态：已获用户确认。内部单目标连接 owner 与公开静态出站组装均已实现；公开 Open 与动态路由仍待后续切片。

## 本次只裁决一个问题

“断线自动重连”是否采用按需恢复：没有请求时不主动拨号；下一条尚未发送的请求需要连接时，由基础设施自动尝试建连一次。

采用按需恢复，不增加后台永久拨号循环。这里“一次”指一次有有限超时的 Dial 操作，不承诺操作系统只发送一个网络包，也不限制标准拨号器内部的地址选择。

## Skynet 的实际做法

只读参考：`../skynet/service/clustersender.lua` 与 `../skynet/lualib/skynet/socketchannel.lua`。

- `clustersender` 的普通 `req` 和 `push` 都调用 `channel:request`，初始化 channel 时没有主动调用 `connect`。
- `channel:request` 首先调用 `block_connect(self, true)`；连接可用时复用，否则进入单轮建连。建连失败报错，不在这个普通请求路径中无限循环。
- `block_connect` 用 `__connecting` 合并其他 coroutine 的建连等待；等待者通过 `skynet.wait/wakeup` 挂起和恢复。
- `try_connect` 也支持未设置 `once` 时的循环等待模式，但不能把这一能力误读为普通 Cluster 请求默认永久重试。`connect_once` 还支持备用地址及认证；GSR 本切片不引入这些能力。
- 写入失败走 `sock_err`，关闭 channel socket 并唤醒其等待者，不把已经写入的业务请求自动再发一遍。

Skynet 依赖 Lua coroutine 与 socket 调度。GSR 可以沿用按需连接、连接复用和失败不重放；不照搬 coroutine 等待表。现有每目标一个 NodeSender worker 已串行处理出站请求，连接组件不需要再加一层业务队列。

## 已确认的可观察行为

1. 有可用连接：直接使用；没有连接：当前请求触发一次有限建连。
2. 建连失败：当前 Call 完成并保留底层错误；当前 Send 的 admission 返回值不变，错误进入 A 侧基础设施诊断。不批量失败同节点排队请求。
3. 后续请求：仍在原有有界队列中，轮到它时可以触发新的建连尝试。这是它的首次发送，不是重放前一个失败请求。
4. 空闲断线：清理旧连接已绑定等待，不启动周期性拨号任务。后续请求到来时自动恢复连接。
5. 未发现断线而尝试写入失败：结束当前发送尝试，不为这条请求重连再发；之后的请求才有机会使用新连接。
6. Call 原有总 deadline 不重置。建连前和实际绑定写入前检查等待是否仍有效；建连过程中调用方已结束等待，成功得到的连接也不能继续发送该已取消请求。

建连本身必须有有限上限并能由连接 owner 关闭取消；不能因某条 Call 已结束而让其 Dial 无限占住同节点 worker。具体超时配置和公开组装签名不在本文定稿，本轮不新增公开 API。

## 用业务场景理解

| 场景 | 推荐行为 |
| --- | --- |
| A 第一次给 B 发消息 | A 自动连接 B，不要求 A open 或配置本地 NodeID。 |
| B 没启动，A Send 一条通知 | Send 接纳后 A 继续工作；建连失败留基础设施记录，不等 B 启动，也不补发该通知。 |
| B 后来启动，A 又发一条新通知 | 新通知触发建连，成功后发送；无需业务手动调用 reconnect。 |
| A Call B 查背包，已写入后连接断开 | 当前 Call 返回连接错误；不自动再执行一次查背包，更不会把同样策略隐式用于扣款。 |
| A 与 B 空闲一小时 | 不为了恢复空闲连接持续拨号；下次请求可能承担建连延迟。 |

## 代价与下一切片门禁

优点是没有额外后台重试 owner、定时器或第二层队列。代价是断线后的首个请求承担建连延迟；同节点其他出站请求在该次有限 Dial 后才能推进，但其他节点的 sender 不受影响。目标持续不可达且请求密集时，可能逐条触发失败拨号；按需连接不是限流器，本切片不暗中增加熔断或冷却语义。

内部 `outboundPeer` 负责单目标 Dial 取消、连接替换、唯一响应读循环、关闭与等待；继续复用共享 ClusterCallRegistry 和现有连接归属，不增加 wire 身份、Epoch 或业务重试。每次替换先等待旧响应读循环退出，不积累旧连接任务。

测试门禁包括：首次发送建连、后续复用、失败只结束当前 Call、Send 失败诊断、下一请求恢复、取消后不写入、半写失败不重放，以及 Dial/Read 期间关闭不泄漏。公开 TCP Transport、路由热更新和生产认证不在该最小切片内。

内部配置显式要求正数 Dial/Write timeout，未引入公开默认值。Dial 使用标准 `net.Dialer.DialContext`；测试替身必须遵守 context，不为强杀不合作的拨号器另开 goroutine。Call 在 Dial 期间结束等待不会直接取消此连接级 Dial，但写入前会再次检查，Dial 最迟受自身有限超时或 owner 关闭取消约束。

同步发送错误由 NodeSender 原有 Failures 出口记录；响应坏帧、错归属和连接终止使用 owner 持有的有界非阻塞诊断出口，满载累计丢弃数。读循环 panic 转成基础设施错误并关闭连接、清理其等待；owner 关闭在所有生产者退出后关闭诊断出口。
