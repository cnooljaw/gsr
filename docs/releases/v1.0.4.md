# GSR v1.0.4 发布说明

版本：`1.0.4`（见 [VERSION](../../VERSION)）。发布日期：2026-11-13。阶段：正式内部发布。附注标签 `v1.0.4` 固定发布代码，旧标签保持原样。

## 相对 v1.0.3 的主要变化

1. **有界发送后关闭**：`gate.ClientSession.SendAndClose(frame)` 原子接纳唯一末帧，封闭新发送和入站接纳，保留已接纳队列 FIFO，写完后关闭连接。接纳时复制字节快照，返回 nil 不代表客户端收到或处理。
2. **关闭总预算**：`gate.Config` 和 `gsr.GateConfig` 新增 `SendAndCloseTimeout`，零使用一秒、负数拒绝。预算从接纳起覆盖正在写的旧帧、队列、末帧和关闭；能中断阻塞旧写，不逐帧续期。对端断开、显式 Close、写失败或节点停机可提前中止。
3. **Protobuf 错误策略**：新增 `WithErrorPolicy`、`ReplyError` 和 `ReplyErrorAndClose`。策略在尚未成功响应的错误路径同步执行；终止响应只编码、尝试一次，保留 RequestID 和安全文案，不泄漏原始业务错误。
4. **业务接入规范**：明确 Agent closing、排队请求拦截、等待断线通知后清理退出，以及替换固定延时 failureCloser 的步骤。Gate 只管连接，协议层只管编码及错误处理，业务继续拥有领域规则和清理路由。

## 升级与兼容

```sh
go get github.com/cnooljaw/gsr@v1.0.4
```

**本版扩展 ClientSession 方法集，有 Go 源码兼容影响。** 自行实现该接口的业务适配器和测试替身须补充 SendAndClose；不能用 `Send; Close` 冒充顺序关闭。原 Close 保持可立即中止的语义。

NewDispatcher/MustDispatcher 增加 variadic options，原普通调用保持不变；保存其精确函数类型的代码需同步调整。未配置策略的 Send-only 接线保持旧行为；显式配置策略却缺少 SendAndClose/Close 能力时，构造返回 ErrCloseUnsupported，Must 构造按约定 panic。

选择 ReplyErrorAndClose 时，可关联请求得到唯一安全 ErrorResponse；无法解码 Envelope、无 RequestID 或已知 Notify 时直接 Close，不使用部分解码信息伪造响应。编码/末帧接纳失败不递归回错，原始错误与发送/关闭错误保留供诊断。已经成功响应的请求不追加错误或再次执行策略。

末帧沿用单帧和队列字节上限，超限返回原错误并封闭、异步关闭；不绕过容量、改投或重试。重复 Send/SendAndClose 返回 ErrClientSessionClosed，不追加帧、不延长期限。断开仍使用原 ClientDisconnectedCommand，不增加业务回调。

业务须先设置 closing，拦截已入 Agent Mailbox 的后续客户端业务，但继续处理必要清理 Command。**不要在 SendAndClose 接纳后立即 Exit 或 Close**，以免 OnStop.Close 中止末帧；等待断线通知后执行幂等 Leave、条件 Unbind 和退出。未知 Join、旧登录隔离和业务结果恢复不归 Gate 判断。完整规则见 [业务接入规范](../guides/SEND-AND-CLOSE.md) 和 [ADR 0015](../adr/0015-send-and-close.md)。

本次不增加 Sproto 协议层错误策略，Sproto 可使用 Gate 字节能力，不生成 Protobuf ErrorResponse。Core Reply、Cluster wire、服务池语义、既有客户端字节协议和 gosproto v1.0.1 依赖保持不变。

## 发布验证

环境：Go 1.24.13，darwin/arm64；最低 Go 版本仍为 1.24.0。

- `GSR_PROCESS_TEST=1 go test -race ./... -timeout=2m`：通过，含末帧顺序/快照/容量、并发接纳、阻塞旧写预算、MAC/Plain 安全错误后断线与原通知链路，以及双进程正常停机/强杀恢复；Gate 约 35 秒，双节点约 17 秒。
- `go vet ./...`：通过。
- WebSocket 示例 `npm run test:sproto:integration`：四项通过、零跳过，含 Plain/MAC 真实 Go↔TS 链路。
- 复用同次 TS 构建，`node --test client/dist/auth_vectors.test.js client/dist/secure_auth.test.js`：五项通过、零跳过。
- Markdown 本地链接/锚点、diff、版本入口与模板固定标签目标：检查通过。

未运行专项负载、Gate 长期压力、真实 MySQL/Redis 或独立 gosproto 官方编解码矩阵。

业务项目迁移、gsrdemo 的领域回归、TS CLI 业务流程和目标节点部署需由业务项目升级后另行验收。本次不以 GSR 测试替代业务清理、一致性或目标部署容量验证。
