# GSR v1.0.3 发布说明

版本：`1.0.3`（见 [VERSION](../../VERSION)）。发布日期：2026-11-09。阶段：正式内部发布。附注标签 `v1.0.3` 固定发布代码，旧标签保持原样。

## 相对 v1.0.2 的主要变化

1. **有界 Service 池**：新增 `Node.CreateServicePool(ctx, name, ServicePoolConfig)`，由工厂创建固定数量的独立 Service；外部使用原有 CallName 或 Cluster Call，内部按名称轮询到成员，各成员仍串行执行并由 Runtime 自动回复。
2. **实例容量与失败回收**：每成员可配置 MailboxCapacity；创建阶段预留名称，失败或取消时撤销名称并回收已创建成员。Core 增加基础设施入口 `CreateServiceWithConfig` 和 `StopServices`，不把池或名称引入 Core，也不向业务暴露 goroutine 或手工 Reply。
3. **可运行示例**：新增 `examples/service-pool`，展示两个独立调用者通过普通 CallName 使用同一池名、成员独占状态和结果收集后的正常关闭。
4. **文档重组**：按 guides、design、development、validation、releases 分类；合并 Cluster RFC，清理过时路线图和执行流水，保留 ADR、版本迁移及带口径限制的性能资料。

## 接入与升级

```sh
go get github.com/cnooljaw/gsr@v1.0.3
```

v1.0.2 的业务接口继续使用原写法，服务池是可选能力。创建示例：

```go
err := self.Node().CreateServicePool(ctx, "workers", gsr.ServicePoolConfig{
    Size:            4,
    MailboxCapacity: 32,
    NewService: func() gsr.Service {
        return newWorkerService()
    },
})
```

工厂须返回独立、非 nil 的 Service 指针，资源初始化放 OnStart。业务实现显式 Handle，通常由具名 Dispatcher 分发；多个成员共享的数据库等依赖须由业务保证并发安全。完整接线见 [使用指南](../guides/SERVICE-POOLS.md) 和 [可运行示例](../../examples/service-pool/README.md)。

池只选择一次成员，选中 Mailbox 满就返回 ErrMailboxFull，即使其它成员还有空间也不改投。它不保证全池顺序、不重放、不自动补员，也不自动拆分单次请求。同步 Call 仍阻塞调用方 Service；事务、幂等、业务顺序与重试由业务定义，超时不表示目标未执行。

从 v1.0.0 或 v1.0.1 升级仍须应用 [Node 入口迁移](v1.0.1.md#升级注意) 和 [Gate 安全模式命名迁移](v1.0.2.md#升级注意)。gosproto 依赖继续固定 v1.0.1，无本地 replace；Cluster wire、Source 绑定及 Gate 客户端协议不因本版改变。

## 发布验证

环境：Go 1.24.13，darwin/arm64；最低 Go 版本为 1.24.0。

- `GSR_PROCESS_TEST=1 go test -race ./... -timeout=2m`：通过，含服务池、示例、双节点及双进程正常停机/强杀恢复；Gate 约 35 秒，双节点约 19 秒。
- `go vet ./...`：通过。
- WebSocket 示例 `npm run test:sproto:integration`：四项通过、零跳过，含 Plain/MAC 真实 Go↔TS 链路。
- 复用同次 TS 构建，`node --test client/dist/auth_vectors.test.js client/dist/secure_auth.test.js`：五项通过、零跳过。
- Markdown 本地链接/锚点、diff 和版本入口一致性：通过。

本次不重跑专项负载、Gate 压力、独立 gosproto 官方 C/Lua 与完整编解码基准，也不启用真实 MySQL/Redis 环境。已有本机样本不构成目标部署容量、跨机器故障或完整业务一致性承诺；范围见 [验证覆盖](../validation/COVERAGE.md)。
